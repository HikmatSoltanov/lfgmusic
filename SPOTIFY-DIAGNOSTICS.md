# Уточнение причины Spotify HTTP 403

Это небольшое обновление для уже установленной версии с персональными аккаунтами и /spotify confirm. Оно не меняет подписку, права Spotify или настройки хостинга. Вместо общего сообщения показывает краткую причину из ответа Spotify и endpoint, который её вернул. Если Spotify не прислал причину, это явно указано. Токены, email и параметры callback скрываются из диагностического сообщения. Исходный ответ целиком и Authorization-заголовки не публикуются.

1. Остановите сервер Wispbyte.
2. Распакуйте `lfgmusic-spotify-diagnostics.zip` в `/home/container` с заменой `src/spotify.ts`, `dist/src/spotify.js`, `dist/src/spotify.js.map`.
3. `.env`, ключ шифрования, `data/`, `media/`, cloudflared и Startup Command не меняйте. Новых зависимостей и команд нет; повторная регистрация Discord не нужна.
4. Запустите сервер обычной командой с `scripts/start-with-tunnel.mjs`.
5. Выполните **новую** `/spotify login` в Discord и пройдите авторизацию. Не перезагружайте старый callback: OAuth state одноразовый и уже использован.
6. Если снова отказ, скопируйте только текст ошибки со страницы, без адресной строки с code/state. Причина вида `User not registered in the Developer Dashboard` указывает на допуск Spotify-пользователя в User Management. Причина про scopes требует нового OAuth-согласия. Причина про Premium требует проверки условий для аккаунта и владельца приложения. Если причина общая/отсутствует, отдельно проверьте настройки приложения: код не объявляет подписку или allowlist установленной причиной без ответа Spotify.

Сборка и 26 автоматических тестов проходят, включая plain-text и JSON 403, маскирование секретов и остальные проверки OAuth/SQLite/изоляции аккаунтов. Живой ответ Spotify доступен только на вашем Wispbyte при следующей попытке; локальные тесты используют подменённый Spotify transport.
