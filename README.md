# LFG Music — личный Spotify-плеер и Discord Voice

Полный проект на Node.js 24 LTS и TypeScript для Windows 10/11 x64. `discord.js`, `@discordjs/voice` с DAVE, SQLite, OAuth 2.0 Authorization Code + PKCE, FFmpeg и Opus.

## Основной сценарий без Jam

Обычный Spotify Premium → `/listen start` → текущий трек и доступная очередь «Далее» → Discord Voice. Добавлен аудиодвижок на LavaPlayer, как в MusicBot, с поиском YouTube/SoundCloud. Для новой записи владелец подтверждает источник и право трансляции; сохранённые источники затем используются автоматически. Публичная доступность не означает право трансляции, недоступные/неподтверждённые записи остаются без звука. Полное описание, установка компактного Java-сервиса на Wispbyte и ограничения памяти: [LISTEN-UPDATE.md](LISTEN-UPDATE.md).

## Что возможно через Spotify

Публичный Spotify Web API **не предоставляет создание Jam, приглашение Jam, список участников или аудиопоток песни**. Jam нужно создать в официальном клиенте, а приглашение скопировать вручную. Бот видит доступное состояние плеера **авторизованного ведущего**, а не отдельный поток событий Jam. Приватная сессия, отсутствие активного устройства, ограничения аккаунта или приложения могут скрывать данные. Очередь `/me/player/queue` — очередь плеера ведущего, не список участников Jam.

Spotify Premium и доступ пользователя к приложению могут требоваться для Player API и Jam; ограничения Development Mode зависят от текущих правил Spotify. Права на трансляцию записи не возникают из подписки Spotify. Техническая работа с метаданными не означает разрешение Spotify на конкретный сценарий: условия Spotify ограничивают трансляцию, неинтерактивные сервисы и использование контента. Перед использованием режима синхронизации отдельно проверьте применимость условий и получите необходимые разрешения. Бот не извлекает аудио Spotify, не снимает DRM и не использует приватные Jam API.

## Персональные аккаунты Spotify Premium

У каждого Discord-пользователя отдельная привязка. Общие `SPOTIFY_CLIENT_ID` / `SPOTIFY_CLIENT_SECRET` идентифицируют приложение бота; пользователи не вводят свои пароли, Client Secret или чужие токены. Источник сессии — аккаунт Discord-пользователя, который запустил сессию, а не аккаунт разработчика бота. Эта возможность относится и к обычному Spotify-плееру, Jam для входа не нужен.

Новая процедура: `/spotify login` → согласие в Spotify → страница с именем выбранного Spotify Premium → `/spotify confirm` в Discord → личный ответ с именем и ID Spotify → кнопка **«Это мой Spotify»**. До этой кнопки новая привязка не активна. Кнопку может подтвердить только тот Discord user ID, для которого создан запрос. Имя на странице и в подтверждении нужно проверить: OAuth подтверждает контроль над аккаунтом, а не юридическое совпадение личности владельцев Discord/Spotify. Не пересылайте личные ссылки.

Один Spotify account ID может быть привязан только к одному Discord user ID одновременно. Попытка привязать уже занятый аккаунт отклоняется; привязка не переносится автоматически. Для смены владельца сначала нужен `/spotify logout` у прежнего Discord-пользователя. Переподключение того же аккаунта к своему Discord разрешено. При замене своего Spotify старое соединение сохраняется до успешного подтверждения нового.

`GET /me` с `user-read-private` проверяет `product=premium` перед подтверждением и повторно перед использованием API, если прошло более пяти минут с проверки. Бесплатные аккаунты не активируются. Если Spotify не возвращает тип подписки или не разрешает endpoint, проверить Premium нельзя — подключение отклоняется, а не считается Premium по умолчанию. Наличие Premium не отменяет ограничения приложения, владельца и Development Mode; разрешённых пользователей при необходимости добавляет владелец приложения в Dashboard.

Токены, кандидат на привязку и профиль шифруются AES-GCM. Для ограничения повторной привязки хранится HMAC account ID. Обновления привязки и токенов атомарны. Подтверждение одноразовое и живёт 10 минут. Logout удаляет токены, профиль и pending-запросы; не затрагивает других пользователей. После обновления старые неподтверждённые привязки нужно авторизовать заново с новым scope и подтвердить. База мигрирует добавлением таблиц; удалять её или менять TOKEN_ENCRYPTION_KEY не требуется.

Это обновление защищает привязки аккаунтов. Автоматический поиск аудио во внешних источниках и полное копирование списка «Далее» не реализованы: текущий `mirror` следует текущему треку и позиции только при наличии точного разрешённого файла.

## Режимы

| Возможность | `real` — Real Spotify Jam | `voice` — Discord Voice Jam | `mirror` — Jam → разрешённый каталог |
|---|---|---|---|
| Настоящее приглашение Jam | Вручную из Spotify | Не создаётся | Вручную из Spotify |
| Выбор треков участниками через Spotify Jam | Да, в Spotify | Нет, независимая очередь Discord | Да, бот наблюдает плеер ведущего |
| Звук | В Spotify у слушателей | Разрешённые локальные записи в Discord | Точное локальное соответствие текущему Spotify track ID |
| Пауза / пропуск | В Spotify | Команды / кнопки бота | В Spotify; бот следует состоянию |
| Нет разрешённого аудиофайла | Не имеет значения | Отказ добавить | Тишина и объяснение |
| Любая песня Spotify в Discord | Нет | Нет | Нет |

В `mirror` бот по умолчанию опрашивает плеер каждые 5 секунд, следует смене трека, паузе и продолжению, а при расхождении позиции более 2,5 секунд перезапускает локальный декодер с нужной позиции. Это приближённая синхронизация с задержкой опроса и Discord Voice, а не синхронный поток Spotify Jam. `/pause`, `/resume`, `/skip` в этом режиме отключены: управляйте в Spotify. После потери доступа к Spotify звук останавливается, чтобы не продолжать устаревший трек.

[JMusicBot](https://github.com/jagrosh/MusicBot), приведённый как пример, использует Java/JDA и LavaPlayer для сторонних источников. Он не добавляет Jam API или право на аудиопоток Spotify. Этот проект написан самостоятельно на запрошенном стеке; YouTube-поиск, скачивание треков Spotify и случайный подбор похожей песни здесь отсутствуют.

## Хостинг Wispbyte / Linux

Инструкции загрузки, команды установки/запуска, настройки выделенного порта и HTTPS OAuth: [HOSTING.md](HOSTING.md). Шаблон конфигурации: `.env.hosting.example`. Доступность Node.js 24, FFmpeg и UDP зависит от тарифа.

## Быстрый старт Windows

1. Установите [Node.js 24 LTS x64](https://nodejs.org/) и FFmpeg. Например, `winget install --id Gyan.FFmpeg -e`. Откройте новый терминал. `node --version` должен показывать `v24…`, `ffmpeg -version` — версию FFmpeg. Если PATH не настроен, укажите полный путь к `ffmpeg.exe` в `FFMPEG_PATH` (без внешних кавычек в самом значении).
2. Распакуйте проект в доступный для записи каталог и запустите `install.bat`. Он выполняет `npm ci`, создаёт `.env`, генерирует ключ шифрования, собирает проект и проверяет зависимости. Существующий `.env` не перезаписывается.
3. Создайте Discord Application и Spotify Application по инструкциям ниже. Заполните `.env` локально; токены не отправляйте в чат и не публикуйте в Git.
4. Запустите `register.bat`, затем `start.bat`.
5. Войдите в обычный голосовой канал своего сервера. Для голосового теста: `npm run demo`, перезапуск бота, `/jam start mode:voice`, `/play query:demo-tone`. Будет короткий тихий тестовый сигнал, не песня Spotify.
6. Для Spotify: `/spotify login` → откройте личную ссылку на том же компьютере → проверьте свой Discord ID на странице → разрешите доступ → `/spotify confirm` → «Это мой Spotify». Создайте Jam в Spotify и выполните `/jam start mode:real`, затем `/jam link url:ССЫЛКА`.
7. Для управления голосовым воспроизведением через Spotify сначала подготовьте соответствия в каталоге, затем `/jam start mode:mirror` и `/jam link url:ССЫЛКА`.

Без Windows-скриптов:

```powershell
npm ci
npm run init:env
# Заполните .env перед регистрацией / запуском
npm run build
npm run doctor
npm run register
npm start
```

`npm run dev` запускает исходники через tsx. При изменениях каталога или `.env` перезапустите процесс. Для остановки используйте Ctrl+C: состояние сохранится. При принудительном завершении возможна потеря последних примерно 10 секунд позиции.

## Discord Application

1. Откройте [Developer Portal](https://discord.com/developers/applications), создайте приложение → Bot → создайте/сбросьте токен. Впишите его в `DISCORD_TOKEN`.
2. Application ID из General Information → `DISCORD_CLIENT_ID`. Это не Public Key.
3. Для быстрого тестирования включите Developer Mode в Discord, скопируйте ID сервера и задайте `DISCORD_GUILD_ID`. Без него команды регистрируются глобально и могут появиться с задержкой.
4. На странице Installation / OAuth2 URL Generator выберите scopes `bot` и `applications.commands`. Пригласите бота на сервер.
5. Дайте боту View Channels, Send Messages, Embed Links, Read Message History, Connect, Speak. Администратор не требуется. Разрешите Use Application Commands участникам.
6. Privileged intents (Message Content, Server Members, Presence) не нужны. Бот использует Guilds и GuildVoiceStates. Поддерживаются обычные voice-каналы, не Stage.
7. При запуске сессии ведущим становится пользователь, вызвавший `/jam start`. Изменять очередь, ссылку и плеер могут он и пользователи с Manage Server, находящиеся в том же голосовом канале. Администратор с Manage Server может завершить осиротевшую сессию без входа в канал. Читать статус/очередь могут участники сервера.

На сервере одна активная сессия; разные серверы независимы. Spotify-привязка персональная по Discord user ID и может использоваться этим пользователем на нескольких серверах. Любой участник может добавить песню в настоящий Jam через клиент Spotify, если это разрешено самим Jam. Прочитать Spotify или токены другого пользователя через slash-команду нельзя.

## Spotify Developer Application и OAuth

1. Откройте [Dashboard](https://developer.spotify.com/dashboard), создайте приложение с Web API. Если Spotify ограничивает создание приложений/доступ вашего аккаунта, это внешнее ограничение, которое код не обходит.
2. Client ID → `SPOTIFY_CLIENT_ID`, Client Secret → `SPOTIFY_CLIENT_SECRET`. Это конфиденциальное серверное приложение; секрет остаётся на машине бота.
3. Добавьте redirect URI **точно** `http://127.0.0.1:8888/callback` и сохраните. `localhost` не используйте. Значение должно совпадать с `SPOTIFY_REDIRECT_URI`, включая путь, регистр и порт.
4. В Development Mode добавьте разрешённых пользователей через настройки приложения, если это требуется. Проверьте текущие требования к Premium, владельцу приложения, количеству пользователей и доступным endpoints в Dashboard и документации Spotify.
5. Запустите бота, вызовите `/spotify login`. Ответ виден только вам. Ссылка живёт 10 минут и показывает Discord ID, к которому будет привязан Spotify. Не открывайте чужие ссылки и не пересылайте свою. Включите Developer Mode Discord и сравните Copy User ID со страницей подтверждения.
6. После OAuth бот проверяет профиль/Premium и шифрует ожидающие access/refresh tokens в SQLite. Для активации выполните `/spotify confirm` и подтвердите показанный аккаунт. Срок access token учитывается; refresh выполняется автоматически с защитой от параллельных обновлений. OAuth state одноразовый, хранится как хеш, verifier зашифрован, используется PKCE S256. Пароль Spotify бот не получает.
7. `/spotify logout` удаляет локальные токены и pending OAuth. Для полного отзыва разрешения удалите приложение на [странице Apps Spotify](https://www.spotify.com/account/apps/).

Scopes: `user-read-private user-read-playback-state user-read-currently-playing`. Бот не запрашивает управление плеером или Spotify streaming. `/jam queue` пытается прочитать официальную очередь ведущего; если endpoint недоступен вашему приложению, возвращает ошибку вместо выдуманной очереди.

### Бот на другом компьютере / в облаке

Loopback callback работает только когда браузер открывается на машине бота. Для удалённого сервера настройте HTTPS reverse proxy с вашим сертификатом:

```dotenv
SPOTIFY_REDIRECT_URI=https://bot.example.org/callback
PUBLIC_BASE_URL=https://bot.example.org
HTTP_HOST=127.0.0.1
HTTP_PORT=8888
```

Добавьте этот **же** redirect URI в Spotify Dashboard. Если reverse proxy находится в другом контейнере, привяжите HTTP к нужному приватному интерфейсу; `0.0.0.0` допустим только с корректными правилами доступа. `/authorize` и `/callback` должны попадать в Node-процесс; запросы и query string callback не логируйте. HTTP-сервер не обслуживает файлы, `.env` или SQLite. `/health` показывает лишь доступность HTTP-процесса, не успешный вход в Discord/Spotify.

Нужны исходящие HTTPS к `discord.com`, `gateway.discord.gg`, домену voice-сервера `*.discord.gg`, `accounts.spotify.com`, `api.spotify.com`, а для установки — `registry.npmjs.org`. Для голосового соединения нужен UDP к Discord Voice. HTTP-прокси сам по себе UDP не заменяет: в ограниченных облачных средах голосовой канал может быть недоступен даже при рабочем REST/Gateway.

## Разрешённый аудиокаталог

Хранятся только файлы, которые вы имеете право транслировать: собственные записи либо записи с подходящим разрешением/лицензией. Бот не может проверить юридическую действительность введённого текста `rights`.

1. Положите аудиофайл в `media/`.
2. Скопируйте `media/catalog.example.json` в `media/catalog.json` и замените поля реальными данными. Поддерживаются MP3, WAV, FLAC, OGG, M4A, OPUS, AAC.
3. Укажите реальную длительность. Проверить: `ffprobe -v error -show_entries format=duration -of default=noprint_wrappers=1:nokey=1 media/my-authorized-track.mp3`, результат в секундах умножьте на 1000.
4. Для Spotify-ссылок и режима `mirror` добавьте каждой записи необязательное поле `spotifyTrackId`: ровно 22 символа ID из `https://open.spotify.com/track/ID`. Это должно быть **точное соответствие той же записи/версии**, включая начало и длительность, а не кавер или ремикс. Подписка Spotify не разрешает скачивание этого файла.
5. Перезапустите бота. Отсутствующий каталог означает пустой каталог, а не скрытый сетевой поиск. Некорректный каталог останавливает запуск с объяснением.

Пример записи без Spotify-соответствия:

```json
[
  {
    "id": "my-track",
    "title": "Моя композиция",
    "artist": "Мой проект",
    "file": "my-track.wav",
    "durationMs": 120000,
    "rights": "Я автор записи и разрешаю её воспроизведение в Discord"
  }
]
```

`/play query:my-track` либо `/play query:Мой проект - Моя композиция`. Для Spotify URL добавьте `spotifyTrackId`, затем используйте полную track-ссылку. При наличии личной Spotify-авторизации бот дополнительно читает название/исполнителя через API; при недоступности API сообщает ошибку. Без авторизации используются заранее указанные метаданные точного соответствия. Поддерживаются также `spotify:track:ID` и локализованные ссылки `open.spotify.com/intl-…/track/ID`.

Воспроизведение по произвольным URL, плейлистам, альбомам и коротким Spotify track-ссылкам не поддерживается. Путь к файлу проверяется через `realpath` и повторно перед воспроизведением; выход через `..` или симлинк за AUDIO_ROOT запрещён. FFmpeg запускается без shell и с протоколами `file,pipe`. Каталог и аудиофайлы должны изменяться только доверенным администратором.

`npm run demo` добавляет **синтезированный тестовый сигнал** и сохраняет существующие записи каталога. Повторная генерация не перезаписывает файл. Музыки и фиктивного Spotify-соответствия в поставке нет.

## Команды и интерфейс

| Команда | Действие |
|---|---|
| `/jam start mode:real/voice/mirror link:…` | Подключение в voice-канал вызывающего; `real` по умолчанию, ссылка необязательна |
| `/jam link [url:…]` | Показать или записать приглашение Jam; только `real`/`mirror` |
| `/jam stop` | Завершить сессию, убрать кнопки, удалить сохранённое состояние сессии |
| `/jam status` | Режим, Spotify, voice, текущий трек, диагностированная ошибка |
| `/jam queue` | Очередь Discord либо доступная очередь плеера ведущего Spotify |
| `/spotify login` | Персональная одноразовая ссылка OAuth |
| `/spotify confirm` | Проверить аккаунт и активировать личную привязку кнопкой |
| `/spotify logout` | Удалить свою локальную авторизацию |
| `/play query:…` | Добавить трек из каталога; только `voice` |
| `/skip`, `/pause`, `/resume` | Управлять плеером Discord; только `voice` |

Embed содержит название/исполнителя, прогресс, Spotify-обложку и ссылку на трек при доступности Spotify, индикаторы подключения и приглашение. Для аудиокаталога обложка не выдумывается. Ссылка Jam валидируется по HTTPS и доменам `spotify.link` / `open.spotify.com/jam/…`, но короткая ссылка может оказаться не Jam или истечь: подтвердить её тип/действительность через публичный API нельзя.

Одна панель редактируется на месте: смена состояния обновляется автоматически, прогресс — примерно каждые 15 секунд. Удалённая панель создаётся заново; старые кнопки не управляют новой сессией. На панель управления распространяются те же проверки прав и канала, что и на slash-команды. В `real` и `mirror` кнопки паузы/пропуска отключены: управление остаётся в Spotify.

## SQLite, восстановление и ошибки

- `data/bot.sqlite`: зашифрованные токены и состояние каждой сессии (сервер, ведущий, каналы, message ID, приглашение, очередь, текущий трек, позиция, пауза). Сохраняется при изменениях и каждые 10 секунд.
- `TOKEN_ENCRYPTION_KEY`: AES-256-GCM, генерируется локально. Не меняйте его при существующих токенах. Храните `.env` и согласованную резервную копию SQLite/WAL закрытыми ACL Windows; шифрование не защищает от администратора машины.
- При штатном перезапуске бот восстанавливает каналы/панель. `voice` продолжает файл с сохранённой позиции, включая паузу; `real`/`mirror` заново читают актуальный Spotify. Обычный `/jam stop` удаляет сессию, но сохраняет авторизацию Spotify.
- При удалённом канале или потерянных правах восстановление сообщает проблему и сохраняет запись. Исправьте права/канал и перезапустите процесс. Запуск новой сессии на этом сервере заменит старую сохранённую запись.
- Discord Gateway переподключает discord.js. Voice пробует восстановить transport и до пяти rejoin; если Discord исключил бота или запретил подключение, гарантировать восстановление нельзя. Состояние не удаляется; выполните stop/start или перезапустите после исправления причины.
- Spotify 429 учитывает Retry-After для всего клиента, 401 вызывает одно обновление токена, повторные 401/403 не зацикливаются. Таймаут сетевого запроса — 12 секунд. Повторный вход после отзыва доступа — `/spotify login`.
- Повторы текущего или ожидающего трека по ID каталога запрещены, длина очереди — до 100. После проигрывания трек можно добавить снова.
- Очередь и команды одного сервера выполняются последовательно; ошибка одной операции не блокирует последующие. Ошибки API и декодирования не превращаются в успешный результат.

## Тестирование

Автоматически, без Discord/Spotify-токенов (нужен FFmpeg):

```powershell
npm run check
npm run build
npm test
npm run doctor
```

Тесты выполняют настоящий HTTP OAuth callback с подменённым Spotify transport, проверяют PKCE/state и защиту от повторного использования, AES-GCM/SQLite, пути/симлинки каталога, отсутствие неоднозначных соответствий, 401/403/429, параллельный refresh, logout во время refresh, очередь/паузу/skip/восстановление и изоляцию серверов с подменённым Discord transport. Отдельный тест реально генерирует WAV и пропускает его через FFmpeg → PCM → Opus в voice-плеере. Тест синхронизации проверяет точный Spotify ID, переходы, паузу, продолжение, seek и отсутствие аудио. На Windows тест симлинков пропускается из-за возможного отсутствия привилегии создания симлинков. Это не проверка реального Discord voice-соединения.

Ручной приёмочный сценарий после ввода ваших ключей:

1. `register.bat` → все команды появились; `start.bat` → Discord подключён, OAuth слушает порт.
2. `/spotify login` → свой Discord ID → согласие → проверка Premium → `/spotify confirm` → кнопка «Это мой Spotify». Повторно открыть callback — отказ. Проверить отмену согласия и новую login-ссылку.
3. Создать Jam в Spotify, `/jam start mode:real`, `/jam link`. Другой участник открывает приглашение и добавляет трек через Spotify. Embed должен показать название, исполнителя, обложку и смену состояния. В Discord звук не передаётся.
4. `/jam queue` → очередь ведущего либо конкретная ошибка доступа; `/jam status` → актуальный режим и соединения.
5. `/jam stop`, `npm run demo`, перезапуск, `/jam start mode:voice`, `/play query:demo-tone` → слышен тестовый сигнал. Проверить паузу, продолжение и пропуск. Для очереди из нескольких треков добавьте ещё одну собственную запись.
6. Пока трек в очереди или играет, повторить `/play` с его ID → отказ без дубликата. Несуществующий ID/чужой URL/несопоставленный Spotify ID → отказ без воспроизведения другой песни.
7. Приостановить длинную собственную запись, завершить процесс Ctrl+C и запустить заново → та же панель, очередь, позиция и пауза; продолжить кнопкой.
8. `mirror`: добавьте точное разрешённое соответствие реально доступной вам Spotify-записи. `/jam start mode:mirror` → управлять в Spotify: сменить трек, пауза, resume, seek. Discord должен следовать с задержкой опроса. Перейти на трек без соответствия → тишина и сообщение. Отозвать Spotify-доступ → тишина и ошибка, не продолжение старой песни.
9. Другой участник без Manage Server пробует кнопки/команды → отказ; ведущий из другого voice-канала → отказ. Администратор проверяет stop без входа в канал.
10. Подключить второй Discord-сервер → независимые очереди и панели. Проверить восстановление после перезапуска сразу двух сессий.
11. Проверить потерю сети, исключение бота из voice, удаление панели, запрет Send Messages и последующее восстановление прав. При обычном кратком сетевом сбое ожидается переподключение; при постоянном запрете — диагностическая ошибка.
12. `/spotify logout` → токенов больше нет, Real Jam сообщает об отсутствии доступа; открыть Apps Spotify и отозвать разрешение. `/jam stop` → бот отключён, кнопки убраны.

Проверка с реальными Discord/Spotify и Windows требует ваших аккаунтов и запуска на соответствующей системе. Включённые автоматические тесты не подменяют эту проверку.

## Структура проекта

```text
src/
  index.ts       Discord Gateway, команды, права, блокировки, жизненный цикл
  commands.ts    Описание slash-команд
  register.ts    Регистрация команд Discord
  config.ts      .env и проверка конфигурации
  store.ts       SQLite, шифрование токенов, одноразовый OAuth state
  spotify.ts     OAuth, refresh, Web API, cache, rate limit
  oauth.ts       HTTP consent/callback и health
  catalog.ts     Разрешённые файлы и точные соответствия Spotify
  voice.ts       Discord Voice, DAVE, FFmpeg, Opus, reconnect
  mirror.ts      Синхронизация метаданных с разрешённой записью
  session.ts     Состояние, очередь, Embed, восстановление
  types.ts       Типы, URL-проверки и общие функции
  doctor.ts      Диагностика без вывода секретов
scripts/         Безопасная подготовка .env и генератор тестового сигнала
test/            Автоматические тесты
media/           Ваши разрешённые файлы и catalog.json (не включаются в Git)
data/            Локальная SQLite (не включается в Git)
.env.example     Образец конфигурации
*.bat            Установка, запуск, регистрация, тестирование в Windows
```
