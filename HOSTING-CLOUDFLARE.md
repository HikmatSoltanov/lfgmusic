# Постоянный Cloudflare Tunnel на Wispbyte

Этот вариант запускает бота и коннектор cloudflared в одном Linux x64-контейнере без systemd/sudo. Используется официальный cloudflared 2026.10.5, SHA-256 проверяется до каждого запуска. Источник: https://github.com/cloudflare/cloudflared/releases/tag/2026.10.5 . Бинарник в дополнении проверен по SHA-256 `e1bc0cf084fd9e590554fe769a86b1db46701c3f847a43d902f7b974a4e16298`. cloudflared распространяется Cloudflare по Apache-2.0; текст лицензии включён в `bin/CLOUDFLARED-LICENSE`.

## Установка дополнения

1. Остановите сервер в Wispbyte.
2. Загрузите `lfgmusic-cloudflare.zip` и распакуйте **в корень** `/home/container`. После распаковки должны появиться `scripts/start-with-tunnel.mjs`, `scripts/install-cloudflared.mjs` и `bin/cloudflared-2026.10.5-linux-amd64`. Существующие `.env`, `data/`, `media/` и исходники бота не удаляйте. В дополнении нет токенов или базы.
3. В Cloudflare Zero Trust создайте Tunnel типа cloudflared с именем `lfgmusic`. На экране установки коннектора скопируйте **только секретный токен**, который указан после `service install` либо `--token`. Не копируйте всю Windows/Linux-команду. Устанавливать Windows-службу на ПК или запускать `sudo` на Wispbyte не требуется.
4. Добавьте токен в приватный `.env` на Wispbyte:

   ```dotenv
   CLOUDFLARE_TUNNEL_TOKEN=ВСТАВЬТЕ_СВОЙ_ТОКЕН
   ```

   Не присылайте токен в чат и не вставляйте его в видимое поле Startup Command. Это тот же токен для любого варианта установки коннектора; его не нужно получать отдельно для Linux. При утечке перевыпустите токен туннеля в Cloudflare.
5. Настройте остальные значения в существующем `.env`:

   ```dotenv
   HTTP_HOST=0.0.0.0
   HTTP_PORT=12465
   PUBLIC_BASE_URL=https://music.2gshop.uk
   SPOTIFY_REDIRECT_URI=https://music.2gshop.uk/callback
   ```

   `12465`, `2gshop.uk` и поддомен `music` — значения текущей установки; если ваши назначения меняются, используйте реальные. Discord/Spotify-ключи и TOKEN_ENCRYPTION_KEY сохраните прежними.
6. Startup Command в Wispbyte:

   ```bash
   cd /home/container && node scripts/start-with-tunnel.mjs
   ```

7. Запустите сервер. Скрипт проверит бинарник и его права на выполнение. Если бинарника нет, скачает **тот же закреплённый официальный релиз по HTTPS** и проверит SHA-256; при несоответствии не запустит его. Установка npm-зависимостей уже должна быть выполнена ранее. Запускаются два дочерних процесса. При завершении одного останавливается второй; панель видит ошибку. SIGTERM/SIGINT останавливает оба, давая боту сохранить состояние.
8. Дождитесь `Registered tunnel connection` в журнале и состояния Connected / Healthy в Cloudflare. `Discord подключён` подтверждает только Discord, а не туннель. При недоступном исходящем TCP 7844 коннектор может повторять соединение: проверьте ограничения тарифа/поддержку Wispbyte. Используется HTTP/2 поверх TLS, сертификаты проверяются. Никаких отключений TLS-проверки нет. Требования к Discord Voice UDP остаются отдельными.

## Публикация адреса

В мастере туннеля нажмите Next; либо откройте существующий туннель → Published application routes / Public Hostnames → Add:

- Subdomain: `music`.
- Domain: `2gshop.uk` (домен должен быть Active в Cloudflare).
- Path: оставить пустым.
- Service Type: `HTTP`.
- Service URL: `127.0.0.1:12465` (в некоторых формах полный URL `http://127.0.0.1:12465`).

Сохраните. Коннектор находится **на том же Wispbyte-сервере**, что и бот; поэтому нужен loopback контейнера, а не внешний IP. Cloudflare создаст нужную DNS-запись маршрута. Не заменяйте её A-записью на IP и не добавляйте HTTP-порт к публичному HTTPS-адресу.

Проверьте `https://music.2gshop.uk/health`: ожидается `{"ok":true}` без ошибок TLS, Access login или 502/1033. Ошибка 1033 обычно означает отсутствие подключённого коннектора; 502 — недоступный origin/неверный локальный порт. Если активирована дополнительная Cloudflare Access-политика, она не должна блокировать Spotify callback; в этой схеме дополнительный Access-login не настраивается. Обработчик `/health` сам по себе не подтверждает OAuth.

После успешной проверки можно закрыть прямой внешний HTTP-доступ, изменив `HTTP_HOST=127.0.0.1` и перезапустив. Туннель продолжит обращаться к loopback; прежняя публичная проверка `http://IP:12465/health` перестанет работать — используйте HTTPS-домен. Порт коннектора не публикуется отдельно.

## Spotify

1. Spotify Developer Dashboard → приложение → Settings → Redirect URIs.
2. Добавьте **ровно** `https://music.2gshop.uk/callback`, нажмите Add и Save. Временный loopback URI можно удалить.
3. Убедитесь, что такой же URI указан в `.env`, и перезапустите процесс после изменения `.env`.
4. В Discord выполните `/spotify login`. Откройте свежую личную ссылку, проверьте свой Discord ID и авторизуйтесь. Ссылка действует 10 минут. После успеха выполняйте `/jam start mode:real` либо подготовьте разрешённый каталог для `mirror`.

## Секреты и границы проверки

Токен передаётся cloudflared через созданный скриптом временный файл в `data/` с правами 0600, не через аргумент командной строки. Файл удаляется при штатном завершении. После SIGKILL временный файл может остаться: храните каталог `data/` закрытым и не публикуйте его архивы. Не включайте debug-логирование cloudflared: оно может содержать URL и заголовки OAuth. Скрипт не запрашивает токен в чате, не меняет nameservers и не управляет вашей учётной записью Cloudflare.

Локально проверены загрузка/хеш и запуск официального бинарника, распознавание CLI-флагов, отказ при отсутствии/невалидности токена, завершение пары процессов и очистка token-файла. Реальное соединение с вашим туннелем, публичным DNS и Spotify должно быть проверено на Wispbyte после настройки. Архитектура, постоянный диск и разрешение запуска коннектора зависят от хостинга.
