# Запуск на Wispbyte / Linux-хостинге ботов

Проект можно запускать в обычном Node.js-контейнере. Доступа к вашей панели у меня нет: доступность Node.js 24, FFmpeg, HTTPS, UDP, постоянного диска и непрерывной работы нужно проверить на **вашем тарифе**. Этот документ не утверждает, что каждый тариф Wispbyte предоставляет эти возможности. На Linux `.bat` не используются.

## Что выбрать в панели

- Тип приложения: Node.js, версия **24 LTS**, архитектура x64 либо другая с доступной DAVE-библиотекой. На Node.js 18/20 проект не запустится; требуются встроенная SQLite и современный Discord Voice.
- Образ с FFmpeg в PATH либо возможность установить доверенный FFmpeg в доступную папку и указать `FFMPEG_PATH`. Скрипт не требует sudo и не скачивает непроверенные бинарники.
- Постоянный диск для `.env`, `data/`, `media/`. Эти папки не должны удаляться при перезапуске, переустановке или обновлении контейнера.
- Разрешённые исходящие HTTPS/WebSocket к Discord и Spotify, UDP к Discord Voice. Работающий текстовый бот не доказывает доступность голосового UDP.
- Для Spotify OAuth — доступный браузеру **публичный HTTPS-адрес**, направленный reverse proxy на HTTP-порт бота. Только Discord Gateway не требует входящего порта, но выбранный встроенный OAuth-сервер требует callback.
- Достаточный лимит CPU/RAM для FFmpeg и Opus; нагрузка растёт с количеством одновременно звучащих серверов. На бесплатном тарифе проверьте условия сна/остановки процесса и ограничения музыкальных ботов.

Если подходящего образа или UDP нет, нужна настройка/помощь поддержки либо другой тариф. Код не может обойти запрет провайдера.

## Загрузка и установка

1. Скачайте `lfgmusic.zip` и распакуйте через файловую панель. **Содержимое папки `lfgmusic`** разместите в рабочем каталоге сервера: рядом должны лежать `package.json`, `package-lock.json`, `src/`, `scripts/`. Не загружайте `node_modules` с Windows. ZIP также содержит готовые JavaScript-файлы в `dist/src/`: можно выбрать entry point `dist/src/index.js`, если панель сама устанавливает npm-зависимости. После изменения исходников потребуется новая сборка.
2. Скопируйте `.env.hosting.example` в `.env`. Не перезаписывайте существующий `.env`. Впишите токены в закрытый редактор файлов или используйте защищённые переменные панели. Не публикуйте их в консоли, снимках экрана или чате.
3. Выберите Node.js 24 и выполните из корня проекта:

   ```bash
   bash scripts/install-host.sh
   ```

   Скрипт выполняет frozen-установку `npm ci --include=dev`, генерирует ключ шифрования, если он пуст в `.env`, собирает проект и проверяет зависимости. `--include=dev` нужен для TypeScript/tsx даже при `NODE_ENV=production`. Существующие настройки и ключ не заменяются. Запускайте установку при остановленном боте. При отсутствии FFmpeg проверьте образ и настройки панели; не отключайте TLS/checksum-проверки.

4. Заполните `DISCORD_TOKEN`, `DISCORD_CLIENT_ID`, при необходимости `DISCORD_GUILD_ID`, затем один раз выполните:

   ```bash
   npm run register
   ```

5. Команда запуска в панели:

   ```bash
   bash scripts/start-host.sh
   ```

   Если панель разрешает только запуск Node-файла, укажите **`dist/src/index.js`**. Если доступны npm-команды, подходит **`npm start`**. Не указывайте `src/index.ts` как обычный JavaScript entry point. Скрипт использует `exec`, чтобы SIGTERM от панели дошёл до бота и состояние сохранилось.

Команды установки не вводятся в уже работающую консоль бота: используйте shell/терминал/установочный шаг панели. Если панель предоставляет только поле startup, выясните у поддержки способ выполнить первоначальный `npm ci` и сборку. Не запускайте установку при каждом автоматическом перезапуске.

## Spotify OAuth на хостинге

Пример для **вашего** домена `https://music.your-domain.tld` и выделенного HTTP-порта `12345`:

```dotenv
HTTP_HOST=0.0.0.0
HTTP_PORT=12345
PUBLIC_BASE_URL=https://music.your-domain.tld
SPOTIFY_REDIRECT_URI=https://music.your-domain.tld/callback
```

Это примеры; не используйте чужой домен и не копируйте порт без проверки. В настройках Spotify Application добавьте **точно то же** значение `SPOTIFY_REDIRECT_URI`. Reverse proxy должен направлять `/authorize`, `/callback` и `/health` на выделенный порт Node-процесса. HTTPS может завершаться на proxy, а внутри контейнера работать HTTP. Не путайте публичный HTTPS-порт с внутренним выделенным портом.

`http://127.0.0.1:8888/callback` в браузере на вашем ПК обращается к вашему ПК, а не к хостингу. Поэтому из коробки loopback-настройки Windows здесь не подходят. Обычный публичный `http://IP:порт/callback` также не подходит: Spotify требует HTTPS для callback вне loopback. Если у тарифа нет публичного HTTPS, нужен поддерживаемый провайдером HTTPS reverse proxy/домен или иной безопасный маршрут callback. Нельзя просто заменить HTTPS на HTTP либо выдумать адрес. Бот с разрешённым аудиокаталогом может работать в `voice` без Spotify-авторизации, но режимы `real`/`mirror` требуют завершённый OAuth.

Токены вводите только в безопасные настройки хостинга/`.env`. Некоторые панели скрывают dotfiles: включите их отображение для `.env`. Если переменные панели заданы, dotenv по умолчанию не перезаписывает их значениями из файла. При использовании `TOKEN_ENCRYPTION_KEY` из панели сохраните **именно этот ключ**: локальный ключ `.env` может отличаться и не использоваться процессом.

## Проверка после запуска

1. В журнале есть «Discord подключён» и «OAuth HTTP-сервер запущен» без ошибок.
2. HTTPS `/health` на вашем домене возвращает `{"ok":true}`. Это лишь HTTP-проверка, не подтверждение работы Discord/Spotify.
3. В Discord `/spotify login` открывает ваш HTTPS-домен и показывает ваш Discord ID. После согласия Spotify — «Spotify подключён».
4. Войти в voice-канал → `/jam start mode:real` → проиграть трек на активном Spotify-устройстве → проверить название и прогресс. Настоящий Jam создаётся вручную в Spotify.
5. Для проверки звука остановить сессию, выполнить `npm run demo`, перезапустить бота → `/jam start mode:voice` → `/play query:demo-tone`. Должен прозвучать короткий тестовый сигнал. Нет звука при исправных Connect/Speak — проверьте UDP, FFmpeg и `npm run doctor`.
6. Для сценария «Spotify управляет, Discord играет» подготовить `media/catalog.json` с точными разрешёнными файлами и `spotifyTrackId`, перезапустить → `/jam start mode:mirror`. Нет соответствия — тишина. Хостинг не добавляет доступ к аудио Spotify.
7. Перезапустить через панель: авторизация и очередь должны сохраниться. При обновлениях исходников сохраняйте `.env`, `data/`, `media/`; не запускайте одновременно два процесса на одной SQLite и одном Discord-токене.

Для автоматических проверок: `npm run check`, `npm test` (нужен FFmpeg). Подробные настройки Discord/Spotify и ограничения описаны в [README.md](README.md).
