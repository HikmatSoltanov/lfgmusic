# Обновление: личный Spotify Premium для каждого Discord-пользователя

## Установка на действующий Wispbyte

1. Остановите сервер через панель. Сохраните закрытую резервную копию `.env` и всей папки `data/` (включая SQLite/WAL, если они есть). Не отправляйте копию в чат.
2. Загрузите `lfgmusic-accounts-update.zip` и распакуйте прямо в `/home/container`, разрешив замену исходников и `dist/src/`. Архив не содержит `.env`, `data/`, `media/`, токенов, ключа шифрования или cloudflared. Существующий коннектор и данные сохраняются. Новых npm-зависимостей нет; повторная npm-установка не требуется.
3. На один запуск поставьте Startup Command:

   ```bash
   cd /home/container && node dist/src/register.js && node scripts/start-with-tunnel.mjs
   ```

   Это обновит slash-команды, добавив `/spotify confirm`. Если DISCORD_GUILD_ID пуст, команды регистрируются глобально и появление новой подкоманды может задержаться. В этом случае можно задать ID своего тестового сервера и выполнить регистрацию для него.
4. Запустите сервер. После успешной регистрации верните обычную команду для будущих запусков:

   ```bash
   cd /home/container && node scripts/start-with-tunnel.mjs
   ```

5. База обновится автоматически добавлением таблиц. **Не удаляйте базу и не меняйте TOKEN_ENCRYPTION_KEY.** Старые привязки без проверенного Spotify ID требуют нового входа; бот не начнёт использовать их без подтверждения. Сохранённые сессии/очереди сохраняются, но Spotify-доступ появится только после подтверждения владельцем.

## Как подключается каждый пользователь

1. В Discord вызвать `/spotify login` от своего Discord-пользователя.
2. Открыть личную ссылку, проверить свой Discord ID, авторизоваться **в своём Spotify**. Если браузер уже вошёл в чужой Spotify, сначала сменить аккаунт в Spotify. Пароль вводится только на официальной странице Spotify, не боту.
3. Бот читает официальный `/me`: нужен `product=premium`. Если Spotify вернул бесплатный аккаунт, не вернул тип подписки или запретил доступ — привязка не активируется. Права `user-read-private` запрашиваются при новом входе.
4. На странице успешной проверки появится имя Spotify и инструкция вернуться в Discord.
5. В Discord вызвать `/spotify confirm`. В личном ответе проверить имя и Spotify ID, затем нажать **«Это мой Spotify»**. Не подтверждать незнакомый аккаунт. Для неверного аккаунта начать `/spotify login` заново с правильным Spotify.
6. Только после этой кнопки аккаунт используется ботом. Код привязывает подтверждение к ID участника Discord; кнопка с чужим nonce не активирует чужой профиль. Подтверждение действует 10 минут и одноразовое.
7. Источник сессии — подтверждённый Spotify пользователя, который запустил сессию. На одном сервере остаётся одна активная сессия. Другие пользователи имеют собственные подключения, но не подменяют аккаунт ведущего автоматически. На разных серверах сессии независимы.

Для отключения своей привязки: `/spotify logout`. Доступ другого Discord-пользователя не изменяется. Одновременно один Spotify ID может принадлежать только одной Discord-привязке; для переноса сначала нужен logout из прежней привязки. Разработчик приложения не получает управление Spotify через чужую slash-команду: токены берутся по ID текущего пользователя/владельца сессии.

## Границы защиты

OAuth доказывает доступ к выбранному Spotify-аккаунту. Код не может установить, что владельцы Discord и Spotify — один и тот же человек по документам; поэтому показ имени и явное подтверждение обязательны. Нельзя гарантировать защиту при передаче доступа к самому Discord/Spotify-аккаунту другому человеку. Не пересылайте OAuth-ссылки. Другой браузер не активирует новую привязку без подтверждения в исходном Discord-аккаунте.

Premium проверяется при авторизации, подтверждении и повторно перед использованием API, если прошло более пяти минут. Premium не обходит разрешения Spotify Development Mode, требования к владельцу приложения и ограничения числа/списка пользователей. Их настраивает владелец в Spotify Dashboard. Это обновление **не устраняет гарантированно прежний HTTP 403**: он может быть связан с доступом самого приложения, а не только подпиской слушателя.

Общие SPOTIFY_CLIENT_ID/SPOTIFY_CLIENT_SECRET остаются одними на приложение. Слушатели не вводят Client Secret; у каждого собственные OAuth access/refresh tokens, зашифрованные отдельно по Discord user ID. Обновление не добавляет аудиопотоки Spotify, автоматический поиск музыки во внешних источниках или полное копирование видимой очереди «Далее». Текущий mirror по-прежнему требует точные разрешённые файлы. У исторической команды `/jam` сохранилось название, но вход в личный Spotify не требует Jam.

## Проверка обновления

Автоматические проверки без реальных аккаунтов: `npm run build && npm test`. Проверяются бесплатные/неопределённые подписки, подтверждение правильным и чужим Discord ID, одноразовость/срок, конфликт одного Spotify ID, разделение очередей и текущих треков, logout, гонки refresh со сменой аккаунта, добавочная миграция старой SQLite. Профиль Spotify в этих тестах подменяется; реальные Premium-аккаунты проверяются после установки.

Ручная проверка: пользователь A подключает Premium и подтверждает; пользователь B подключает другой Premium; каждый видит свой аккаунт при подтверждении. Попытка B использовать Spotify A отклоняется. Бесплатный аккаунт отклоняется до активации. После перезапуска подтверждённые привязки сохраняются. При недоступном `/me` подключение отклоняется с причиной, без фиктивного Premium.
